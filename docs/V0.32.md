# v0.32 development slice

v0.32 improves the existing `kssh-tui` upload workflow without introducing a
second transfer implementation. The remote workspace already supported bounded,
cancellable, resumable `u` / `U` uploads, but the local source path had to be
typed after leaving the alternate-screen UI. v0.32 routes those two existing
source prompts through a bounded terminal local-filesystem picker.

## Added

- `u` opens a local file picker. `Enter` selects a real regular file or enters a
  real directory.
- `U` opens a local directory picker. `Enter` enters a real directory and `s`
  selects the current directory as the recursive upload source.
- `Backspace` / `Left` navigates to the parent directory.
- `p` temporarily suspends the picker and accepts an explicit path jump. This
  also provides a cross-drive escape hatch on Windows instead of assuming the
  current drive is the only filesystem root.
- `r` refreshes the current local directory.
- `q`, `Esc`, and `Ctrl-C` cancel the picker and reuse the pre-existing upload
  prompt contract where an empty source means cancellation.
- Directory listings are capped at 4096 entries. Overflow, read failures, and
  metadata failures fail closed rather than silently omitting entries.
- Names and paths rendered in the terminal escape control characters before
  display.

## Local link boundary

The picker uses `symlink_metadata` for every selected or browsed path.

- Unix symbolic links are shown as link-like entries and cannot be entered or
  selected.
- Windows paths whose metadata carries `FILE_ATTRIBUTE_REPARSE_POINT`, including
  junction/reparse-style entries, are also shown as link-like and cannot be
  entered or selected.
- A file or current directory is revalidated immediately before the picker
  returns it.
- The selected path must be valid UTF-8 because the existing tracked TUI upload
  source/destination contract stores reconstructable paths as `String`. The
  picker does not perform a lossy path conversion.

This is a **picker boundary**, not a claim that the core recursive transfer path
has been redesigned around opened directory handles. Existing transfer/symlink
policy and its existing path-based race model remain unchanged in this slice.

## Preserved transfer semantics

v0.32 deliberately does not rewrite `tui_app`'s transfer state machine. After a
source is selected, the existing code still owns:

- remote leaf-name validation;
- recursive-upload confirmation;
- `TransferTaskManager` registration and retained retry lineage;
- bounded transfer progress;
- `Esc` / `Ctrl-C` cooperative cancellation while a transfer owns input;
- atomic staging and resume/checkpoint behavior;
- remote workspace refresh after successful uploads.

Only the two exact existing upload-source prompts are routed to the picker. All
other line prompts—remote names, confirmation tokens, path jumps, broadcast
commands, and shell-related prompts—retain their existing behavior.

## Download scope

`d` / `D` download destinations remain unchanged in v0.32. Their existing empty
prompt value means "use the default local name", whereas upload's empty value
means "cancel". Reusing the picker cancellation result there without a typed
call-site change would make `Esc` accidentally start a download to the default
path. v0.32 therefore leaves download destination selection alone rather than
introducing a sentinel-path workaround. A later slice can add a typed picker
result directly at the download call sites.

## Validation boundary

Unit coverage includes picker windowing, terminal control escaping, explicit
cancel keys, directory-before-file ordering, Unix symlink classification, and
exact routing of only the two upload source prompt strings to File/Directory
picker modes.

No dependency is added and `Cargo.toml` / `Cargo.lock` are unchanged. Promotion
to `develop` still requires CI, Quality, and the real OpenSSH workflow to acquire
runners, execute repository steps, and pass; `steps=null` platform allocation
failures are not counted as validation.
