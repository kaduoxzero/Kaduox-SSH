# v0.30 development note

v0.30 adds the one OpenSSH Include percent escape that is independent of connection-resolution state.

## Included

- OpenSSH `%%` handling in user-config `Include` paths: two source percent characters collapse to one literal `%`.
- The same behavior for connection resolution and read-only host-catalog discovery because both use the shared Include-path expansion boundary.
- Existing `${ENV}` expansion remains single-pass; percent bytes produced by an environment lookup are appended verbatim and are not rescanned.
- A trailing lone `%` fails closed.
- Final path length remains bounded by the existing 16 KiB Include-path limit after environment and `%%` expansion.

## Still intentionally unsupported

All named OpenSSH Include percent tokens remain fail-closed: `%C`, `%L`, `%d`, `%h`, `%k`, `%l`, `%n`, `%p`, `%r`, `%u`, `%i`, and `%j`.

In particular, `%d` is not approximated with Kaduox-SSH's selected config home. Current OpenSSH derives `%d` from the local passwd record's `pw_dir`, while Kaduox-SSH currently selects its config home from platform environment variables. Those values may differ.

`~other-user/...`, bracket/collation glob expressions, and Match criteria outside the existing bounded subset also remain unsupported.

## Validation boundary

Unit coverage checks `%%` collapse, repeated escapes, composition with `${ENV}`, rejection of named/incomplete percent tokens, non-rescanning of environment-produced percent bytes, and final expanded-size enforcement.

Candidate promotion still requires CI, Quality, and real OpenSSH workflows to acquire runners, execute repository steps, and pass. Jobs that fail before any step executes are platform evidence only and do not qualify the source tree.
