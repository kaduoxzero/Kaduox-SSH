# v0.31 development slice

v0.31 extends the bounded OpenSSH user-config Include preprocessor with the two
target-independent local-hostname percent tokens that can be reproduced without
connection-state approximation.

## Added

- `Include` source `%l` expands to the platform local hostname returned by the
  native hostname API.
- `Include` source `%L` expands to the same hostname truncated at the first `.`.
- Unix uses the platform `gethostname` function directly.
- Windows performs a balanced Winsock 2.2 startup/cleanup around the native
  `gethostname` call; environment variables such as `COMPUTERNAME` are not used
  as substitutes.
- One Include argument observes one hostname snapshot even if it contains both
  `%l` and `%L`, matching OpenSSH's construction of `thishost` and `shorthost`.
- The hostname result is not cached process-wide, so separate Include arguments
  can observe a hostname change made while the client is running.

## Preserved boundaries

- `${ENV}` remains single-pass; bytes emitted by an environment lookup are not
  rescanned as `%l`, `%L`, any other percent token, or another `${...}`.
- `%%` still emits one literal percent.
- `%C`, `%d`, `%h`, `%k`, `%n`, `%p`, `%r`, `%u`, `%i`, and `%j` remain
  fail-closed.
- A trailing lone `%`, missing/malformed environment references, native hostname
  lookup failure, non-UTF-8 hostname bytes, and final paths beyond 16 KiB fail
  closed before filesystem access.
- `%d` is still not approximated with the environment-selected config home;
  OpenSSH obtains it from the local passwd entry's `pw_dir`.
- Target-dependent tokens remain deferred because the read-only host catalog has
  no target context and should not silently diverge from connection resolution.

## Scope

The implementation changes only the existing Include environment/percent scanner
and OpenSSH compatibility documentation. It adds no Rust dependency and makes no
`Cargo.toml` or `Cargo.lock` change.

Promotion to `develop` remains gated on CI, Quality, and real OpenSSH jobs
actually acquiring runners, executing repository steps, and passing. A workflow
failure with no executed steps is treated as platform allocation failure, not as
source validation.
