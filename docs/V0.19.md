# Kaduox-SSH v0.19

## Narrow OpenSSH Match compatibility

v0.19 starts a deliberately bounded OpenSSH `Match` implementation without delegating unsupported structural semantics to `russh-config`.

For connection resolution, the first supported subset is restricted to a trusted root user config that does not use `Include`:

- `Match all`
- one `Match originalhost <pattern-list>` criterion

`originalhost` is evaluated against the command-line/config lookup alias before `HostName` rewriting. Hostname comparison is ASCII case-insensitive. Pattern lists use comma-separated `*` / `?` subpatterns and OpenSSH-style leading `!` negation: a matching negative pattern rejects immediately, otherwise at least one positive pattern must match.

Matching blocks are resolved before the downstream parser sees them. A matching block is represented as an ordered `Host *` block for this one target so existing first-value-wins option merging is preserved; a non-matching block is removed, preventing unsupported `Match` contents from bleeding into a preceding `Host` block.

### Fail-closed boundary

The following remain explicitly unsupported in v0.19 and cause configuration resolution to fail rather than continue partially:

- combining `Match` and `Include` in the root config; correct support requires restoring the containing `Match` state after each included file;
- `canonical`, `final`, `exec`, `localnetwork`, `host`, `tagged`, `command`, `user`, `localuser`, and `version` criteria;
- multiple criteria on one `Match` line;
- criterion negation such as `!originalhost`;
- `criterion=value` forms;
- quoted or backslash-escaped Match arguments.

The existing Include-only path remains unchanged when the trusted root config has no `Match`. A `Match` discovered inside an included file still fails closed through the existing Include resolver.

The Match preprocessor has the same 4 MiB resolved-config output ceiling as the existing OpenSSH config path. One `originalhost` pattern-list is capped at 16 KiB and one subpattern at 1023 bytes. Wildcard matching is memoized so adversarial `*` / `?` patterns do not cause exponential backtracking.

This release does not claim full OpenSSH Match parity. Runtime-dependent criteria such as `exec`, `localnetwork`, canonical/final passes, command/session state, and local-user state require a larger resolver context and remain future compatibility work.
