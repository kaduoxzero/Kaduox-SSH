# v0.33 TUI recursive-download destination picker

## Scope

v0.33 extends the bounded local-filesystem picker introduced for TUI uploads to the recursive directory download (`D`) destination flow.

The single-file download (`d`) prompt is intentionally unchanged in this slice. Its current empty-input contract means "use the default filename" and it has no second confirmation boundary, so mapping picker cancellation onto an empty string would start an unintended download. v0.33 does not introduce a sentinel path or fake transfer failure to work around that semantic mismatch.

## `D` flow

When `D` is used on a selected remote directory:

1. the existing local directory picker opens from the process current working directory;
2. directories can be navigated with the existing picker controls;
3. `s` selects the current real local directory as the parent destination;
4. the operator may keep the sanitized default remote-directory leaf name or enter a different portable leaf name;
5. the existing recursive-download confirmation still requires the exact token `YES`;
6. the existing transfer task manager, bounded concurrency, progress, cancellation, atomic local staging, and retry behavior remain unchanged.

The final destination is therefore `selected-parent / chosen-leaf`, rather than silently downloading the remote directory contents directly into the selected parent.

## Cancellation semantics

Picker cancellation must not be confused with the older empty-path default behavior.

When Esc, `q`, or Ctrl-C cancels the recursive-download destination picker, the TUI records a one-shot cancellation state and returns through the existing path prompt without starting transfer work. The immediately following recursive-download confirmation is automatically answered as not confirmed and consumes that state. The existing workspace therefore reports the operation as cancelled before mutation/transfer begins.

The cancellation state is deliberately scoped to the exact recursive-download confirmation prompt. Upload prompts, shell prompts, remote naming, broadcast input, and unrelated confirmations do not consume or observe it.

## Local path boundary

The v0.32 picker rules remain in force:

- listings are capped at 4096 entries;
- Unix symlinks and Windows reparse-point/link-like entries are display-only and are not entered or selected;
- filesystem and metadata errors fail closed;
- terminal-displayed local names and paths are escaped by the picker;
- `p` can jump to an explicit path, including another drive on Windows;
- selected tracked paths must be valid UTF-8 because resumable TUI task records store exact local paths as strings.

The optional destination leaf must also be portable: path separators, controls, Windows-reserved punctuation/device names, and trailing spaces/dots are rejected rather than interpreted as path traversal or platform-specific aliases.

## Non-goals

v0.33 does not change:

- the `d` single-file destination prompt;
- the core SFTP transfer implementation;
- recursive transfer scheduling or concurrency;
- local atomic download policy;
- transfer task registration/retry semantics;
- Cargo dependencies or `Cargo.lock`;
- the transfer core's existing path-based TOCTOU model.

A future slice can refactor the single-file `d` call site to carry an explicit typed cancellation result before giving it the same picker UX.
