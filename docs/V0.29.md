# v0.29 development note

v0.29 narrows one OpenSSH user-config compatibility gap without broadening the existing Match boundary.

## Included

- OpenSSH-style `${NAME}` environment-variable expansion for user-config `Include` paths.
- The same expansion behavior for target connection resolution and read-only OpenSSH host-catalog discovery.
- Single-pass expansion: bytes returned by an environment lookup are appended verbatim and are not rescanned as nested `${...}` expressions or percent tokens.
- Fail-closed handling for missing variables, empty variable names, unterminated `${...}` syntax, non-UTF-8 environment values, and expansion beyond the existing 16 KiB Include-path limit.
- Existing Include trust, regular-file, cycle, nesting, file-count, glob, and cumulative configuration budgets remain unchanged after expansion.

## Still intentionally unsupported

- OpenSSH `%` Include tokens such as `%C`, `%d`, `%h`, `%k`, `%L`, `%l`, `%n`, `%p`, `%r`, and `%u`.
- `~other-user/...` home-directory expansion.
- Full bracket/collation glob expressions.
- Match criteria beyond the existing bounded `Match all` and single `Match originalhost <pattern-list>` subset.

Percent tokens remain separate because several depend on resolved connection state and OpenSSH parsing passes. v0.29 does not approximate those values.

## Validation boundary

Unit coverage exercises multiple environment references, missing/malformed variables, non-recursive expansion, literal dollar handling, raw percent-token rejection, environment-produced percent bytes, and expanded-size enforcement. Existing Include and Match regression coverage remains in place.

Candidate promotion still requires the repository CI, Quality, and real OpenSSH workflows to acquire runners, execute actual repository steps, and pass. A workflow failure with no executed steps is platform evidence only and is not treated as source validation.
