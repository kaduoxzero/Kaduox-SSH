# Kaduox-SSH v0.23

## Reproducible Rust toolchain boundary

v0.23 removes the moving Rust `stable` compiler channel from the workflows that build, test, audit, and package Kaduox-SSH. Normal CI, Clippy, real OpenSSH integration, dependency audit, and the four-platform release build use Rust **1.98.1** explicitly. The MSRV lane remains Rust **1.85.0** and continues to verify the workspace's declared minimum compiler support separately.

Rust 1.98.1 is intentionally selected instead of 1.98.0 because the Rust project published 1.98.1 on 2026-09-03 as a point release fixing a vtable-generation miscompilation in 1.98.0.

## Dependency audit

Quality no longer delegates auditing to `actions-rust-lang/audit`, whose reviewed composite implementation still invoked `cargo +stable`. The audit job now:

- installs Rust 1.98.1 through the already SHA-pinned `dtolnay/rust-toolchain` Action;
- caches the scanner binary with SHA-pinned `actions/cache` v5.0.1;
- installs exactly `cargo-audit 0.22.0` using `cargo +1.98.1 install ... --locked --no-default-features` on a cache miss;
- executes `cargo +1.98.1 audit --file Cargo.lock`.

This fixes both the compiler used to build the scanner and the scanner version itself. The RustSec advisory database remains an intentionally live security-data input: freezing the advisory database would make the vulnerability check stale and is not part of the build-reproducibility claim.

## Policy enforcement

`scripts/release/test_rust_toolchain_policy.py` fails closed if a protected workflow omits an explicit `dtolnay/rust-toolchain` version, reintroduces `toolchain: stable` or `cargo +stable`, changes the normal 1.98.1 toolchain counts, changes the Rust 1.85.0 MSRV lane, or restores the composite audit Action.

The existing immutable Action policy is updated for the new direct `actions/cache` dependency and exact per-workflow Action occurrence counts.

## Validation status

`integration/v0.23.0-candidate` is wired into CI, Quality, and real OpenSSH push workflows. Promotion remains blocked unless those jobs acquire runners and actually execute checkout, formatting, compilation, tests, Clippy, the pinned dependency audit, Rust toolchain policy tests, and OpenSSH fixtures. A `steps=null`/empty-steps runner allocation failure is neither a pass nor source failure evidence.
