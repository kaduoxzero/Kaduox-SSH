# Kaduox-SSH v0.18

## Sync source preflight

v0.18 hardens application of public or stale `SyncPlan` values before any remote synchronization mutation begins.

Before opening the SFTP mutation phase, every `UploadFile` action is checked against the selected local synchronization root:

- the local root must still be an ordinary directory and must not be a symbolic link or, on Windows, a reparse point;
- every parent component below the root must still be an ordinary directory and must not be a symbolic link/reparse point;
- the final upload source must still be a regular file;
- the current source size must equal the byte count recorded in the plan;
- missing, replaced, link-like, or size-changed upload sources fail the entire apply operation before remote delete, mkdir, or upload actions begin.

This closes a plan-to-apply containment gap where a local directory could be replaced by a symbolic link after planning and redirect an upload source outside the selected local root. It also prevents destructive remote actions from starting before obvious stale-source failures are detected.

This is a fail-closed preflight, not a filesystem transaction. A concurrently modified local filesystem can still change after preflight; fully pinning every source to pre-opened no-follow handles across all supported platforms would require a broader API and execution model. The actual single-file uploader continues to reject a link-like final source at transfer time as a second line of defense.

## Explicit recursive symlink policy

v0.18 also adds the frontend-neutral `SymlinkPolicy` API for recursive transfer and synchronization.

- `Skip` is the compatibility default. Existing recursive APIs retain their current behavior: link entries are never followed and are omitted/skipped.
- `Reject` performs a full source-tree preflight and fails the operation when a symbolic link is encountered. Local scans also reject Windows reparse points.
- recursive upload applies the policy to the local source tree;
- recursive download applies the policy to the remote source tree using SFTP `symlink_metadata` for each entry;
- synchronization applies `Reject` to both the local source tree and the remote tree during planning, and repeats the checks before apply so a strict dry-run cannot silently degrade into skip behavior during mutation.

The original `upload_recursive`, `download_recursive`, `plan_sync_to_remote`, `apply_sync_to_remote`, and `sync_to_remote` methods remain source-compatible and preserve `Skip`. New `*_with_symlink_policy` methods opt into explicit policy without adding a field to `TransferOptions` or `SyncOptions`.

`Follow` and `Preserve` are intentionally not exposed. A safe implementation would need cycle detection, containment rules for link targets, target encoding, overwrite semantics, and platform-specific link/reparse behavior. `Reject` preflights are fail-closed validation rather than filesystem transactions; concurrent mutation after preflight remains a separate TOCTOU boundary.
