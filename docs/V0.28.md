# Kaduox-SSH v0.28 development notes

v0.28 closes an OpenSSH configuration-scope gap by integrating the existing bounded `Match` subset with the trusted `Include` resolver and by preventing included files from escaping an inactive parent Host/Match scope.

## Supported Match subset

v0.28 deliberately does not implement full OpenSSH `Match` semantics. It carries forward the v0.19 subset only:

```text
Match all
Match originalhost <pattern-list>
```

`originalhost` is evaluated against the lookup alias before `HostName` rewriting. The pattern list is ASCII case-insensitive, comma-separated, supports `*` and `?`, and honors leading `!` negated subpatterns.

The following remain fail-closed rather than approximated: `canonical`, `final`, `exec`, `localnetwork`, `host`, `tagged`, `command`, `user`, `localuser`, `version`, combined criteria, criterion negation, `criterion=value`, and quoted/backslash-escaped Match arguments.

## Unified Host / Match / Include resolution

Before v0.28, the connection resolver chose between two preprocessing paths: a Match-only root-file rewrite or an Include-only expander. A config that needed both semantics therefore failed closed even when it used only the otherwise-supported Match subset.

v0.28 replaces that split with one target-specific scope machine. For the current original alias it processes Host, supported Match, and Include directives in lexical order and emits only effective ordinary options into an internal `Host *` stream. The downstream `russh-config` parser still provides first-obtained-value semantics for those emitted options.

Includes reached from an active scope are parsed normally. Host/Match state may change while processing an included file, but the parent file's active state is restored when that Include returns.

## Inactive Include never-match semantics

The previous Include-only expansion could inline structural Host blocks from an included file even when the Include appeared under a parent Host block that was inactive for the target. That created a scope-reentry risk: a child `Host <target>` could become active even though its parent scope did not match.

v0.28 mirrors OpenSSH's never-match property for this boundary. An Include reached from an inactive Host/Match scope is still recursively processed, but child Host/Match directives cannot reactivate configuration for the current target.

Inactive includes are not simply skipped. Their files still pass through the same security and resource boundaries:

- user-config file trust checks;
- Unix uid/mode or Windows owner/DACL validation on the opened file object;
- Include cycle detection;
- nesting/file-count/input/output budgets;
- Include path/glob validation;
- supported/unsupported Match structural validation;
- ordinary option syntax validation.

Thus an inactive included file cannot affect the effective target configuration, but malformed or unsupported configuration does not disappear silently.

## Host catalog boundary

The read-only OpenSSH host catalog keeps its existing Include expansion behavior. It continues to discover concrete Host aliases across the bounded Include graph and marks Match/Include structural configuration for the caller. v0.28 does not make the catalog execute Match conditions because catalog discovery is not target-specific connection resolution.

## Related documentation corrections

The v0.28 audit also corrected stale top-level documentation that understated already-implemented capabilities:

- OpenSSH hashed `@cert-authority` / `@revoked` marker host names (`|1|base64-salt|base64-hmac-sha1`) are already matched exactly with HMAC-SHA1, including `[host]:port` formatting for non-default ports;
- recursive transfer and synchronization already expose explicit `skip` / `reject` symbolic-link policies; neither mode follows symbolic links;
- the remaining symlink work is Follow/Preserve semantics with bounded cycle/escape handling and complete cross-platform target encoding, not the absence of any explicit policy.

## Validation boundary

Unit coverage for the v0.28 resolver includes:

- supported Match inside Include;
- parent Match state restoration after Include;
- inactive Host Include non-reactivation;
- inactive Match Include non-reactivation;
- unsupported Match rejection even inside an inactive Include;
- inactive ordinary-option syntax validation;
- existing Include ordering, cycle, hidden-file, trust, permission, and resource-limit coverage.

No Cargo dependency or `Cargo.lock` change is required.

Candidate promotion still requires CI, Quality, and real OpenSSH jobs to acquire runners and execute actual repository steps. Empty-step runner-allocation failures remain infrastructure evidence and are not treated as successful validation.
