# Kaduox-SSH v0.22

## Immutable validation workflow dependencies

v0.22 extends the immutable GitHub Action boundary from the production release workflow to the workflows that decide whether a candidate is releasable:

- `.github/workflows/ci.yml`;
- `.github/workflows/quality.yml`;
- `.github/workflows/integration-openssh.yml`.

Every external `uses:` reference in those workflows is pinned to a reviewed full 40-character commit SHA and keeps a human-readable upstream version/ref comment. The pinned set includes checkout, Rust toolchain setup, Rust cache, Python setup in release-policy, and the Rust dependency-audit action.

## Exact pin-policy enforcement

`scripts/release/test_action_pins.py` now validates release and validation workflows using an exact expected multiset of `action@sha` references. The occurrence count is part of the policy, so adding, removing, duplicating, or substituting an Action reference requires an explicit policy change in the same review.

The policy fails closed on mutable tags or branches, abbreviated hashes, changed full SHAs that are not explicitly approved for that workflow position set, unexpected external Actions, missing human-readable comments, and unpinned container actions. Repository-local `./...` actions remain tied to the checked-out repository commit.

## Audit-action boundary

The reviewed `actions-rust-lang/audit` commit used by v0.22 pins its internal cache Action and installs `cargo-audit` 0.22.0 explicitly. It still uses the Rust `stable` toolchain channel. Likewise the ordinary CI and release lanes intentionally track Rust stable while the MSRV lane stays fixed at Rust 1.85.0. v0.22 freezes Action implementation commits; pinning the Rust stable compiler version is a separate reproducibility policy decision.

## Validation status

`integration/v0.22.0-candidate` is wired into CI, Quality, and real OpenSSH push workflows. Promotion remains blocked unless those jobs acquire runners and actually execute checkout, formatting, compilation, tests, Clippy, audit, workflow pin-policy tests, and OpenSSH fixtures. A job that finishes with `steps=null` is not treated as either a pass or a source-code failure.
