# Kaduox-SSH v0.25

## Native publisher signing

v0.25 closes the repository-side native signing gap for production release binaries.

Stable SemVer tags without a prerelease suffix require native signing automatically. Windows binaries are Authenticode-signed and RFC 3161 timestamped before packaging. macOS binaries are signed with a Developer ID Application identity, secure timestamp, and hardened runtime, then submitted to Apple notarization with `notarytool`; the release fails unless Apple returns `Accepted`.

Prerelease tags such as `v1.0.0-rc.1` can remain unsigned for pipeline qualification. Setting `KADUOX_ENABLE_NATIVE_SIGNING=true` exercises the same signing path on a prerelease. This opt-in cannot disable signing for a stable tag.

## Credential boundary

No signing key is committed to the repository. Windows PFX and macOS P12/P8 material are accepted only through GitHub Secrets. Non-secret certificate identity, App Store Connect key metadata, and timestamp-service URL are repository variables. Temporary credential files and the macOS signing keychain are removed after use.

See `docs/NATIVE_SIGNING.md` for the exact credential interface.

## Signed-byte packaging

Signing runs after compilation and before smoke testing and packaging. The package manifest therefore records hashes and byte lengths for signed executables rather than unsigned build outputs.

## Published-byte verification

The v0.24 Release Qualification workflow now verifies the native trust boundary on the published archive bytes whenever native signing is required:

- Windows executes SignTool verification with the Default Authentication policy and requires a timestamp;
- macOS performs strict `codesign` verification, checks for a secure timestamp, and asks `spctl` to assess each command-line executable.

These checks do not receive private signing credentials.

## Policy protection

`scripts/release/test_native_signing_policy.py` protects:

- stable-release mandatory signing and prerelease opt-in semantics;
- signing-before-packaging order;
- secret/variable credential boundaries;
- SHA-256 Authenticode and RFC 3161 timestamp requirements;
- Developer ID hardened-runtime signing and API-key `notarytool` submission;
- exact `Accepted` notarization status;
- post-publication signature verification without secrets;
- temporary credential cleanup and isolated macOS keychain behavior.

The test executes in both Quality release-policy and production release preflight.

## Validation status

The signing workflow is now implemented but has not completed a real signing ceremony in this repository because GitHub-hosted Actions jobs continue to terminate before runner allocation with no executed steps. V1 must not claim signed-release qualification until a real Windows Authenticode run, Apple notarization submission, platform verification, and post-publication Release Qualification all execute successfully.
