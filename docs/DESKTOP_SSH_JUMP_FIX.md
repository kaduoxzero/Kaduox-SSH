# SSH 跳转与名称修复（2026-09-08）

## 怎样经跳板登录目标

连接顺序为：本机客户端 → 跳板主机 → 最终目标。每一段均为 SSH，
默认端口 22；每台机器分别使用自己的用户名与凭据。

1. 添加跳板到主机库，保存它的地址、SSH 端口、用户名与密码或私钥。
2. 编辑**最终目标**，在“SSH 连接路径”中新建链，按顺序加入中间跳板。
   不要把最终目标重复加入列表。支持最多 5 台跳板，加 1 台最终目标。
3. 点底部“保存主机/保存修改”即可一起保存正在编辑的链。链不完整或
   保存失败时不保存目标，不再静默退回直连。
4. 连接最终目标。若已经连接，先断开再连接，才会使用新的路径。
   不自动断开旧连接，避免中断终端、文件传输或已有转发。

“转发”页面新增“配置 SSH 跳转”入口，允许选择尚未连接的最终目标。
下方 -L / -R / SOCKS 是服务端口转发，不负责改变已有 SSH 会话的路由。
本地转发的初始值现在是 127.0.0.1:2222 → 目标侧 127.0.0.1:22。
两个入口共享深浅主题，保留现有配色与字体，用真实顺序、用户名、地址和
SSH 端口解释连接路径，不用服务端口冒充额外 SSH 节点。

## 名称与兼容性

主机、跳板链、分组和标签支持中文、字母、数字、空格、半角/全角括号及
`. _ - :`，最多 128 个字符，不接受首尾空格、控制字符、路径分隔符或命令符号。
例如 `ubantu linux（local）` 现在可以保存、重新加载和用于跳板引用。

原有 ASCII 别名继续按原逻辑继承同名 OpenSSH 配置。含中文、空格或括号
的友好名称只用于本地主机库查找和显示，不进入 OpenSSH/shell 解析；它们
使用主机记录中独立保存的地址、用户、凭据和显式跳板链。
OpenSSH 导入别名与 ProxyCommand 的安全限制没有放宽。

存储格式未变，但旧版 CLI/MCP 不认识新允许的名称；与桌面客户端共享
主机库时，应使用同一修复版本构建的 CLI/MCP，不要混用旧二进制。

## 验证

- 本轮 23 项前端测试、13 项主机库测试、25 项桌面后端测试通过，
  TypeScript/Vite build、Rust fmt 与相关 crate 的 clippy（-D warnings）通过。
- 命名回归先复现原错误，再通过名称校验、落盘重读、链引用解析测试。
- 前端回归覆盖：直接保存主机时附带链；空链和保存失败不退回直连；
  未连接目标的 SSH 配置入口；服务转发默认 SSH 22 且使用已连接会话。
- 显式运行真实 Windows → 用户指定的 Ubuntu 跳板 → 已保存 Linux 目标测试：
  跳板登录、跳板至目标 SSH banner、经跳板的目标登录及只读命令、完整链
  上的本地端口转发均成功。并非浏览器预览模拟结果。
- 测试不更改主机库、凭据库或远程 sshd 配置，临时转发结束后关闭。
  主机密钥使用 AcceptNew/既有验证策略；首次出现的密钥会写入本地
  known_hosts，已有密钥不匹配仍拒绝连接。
- 新 release CLI 在独立临时主机库中完成中文/括号名称的新增、再次读取，
  没有改动真实主机库；测试夹具随后清理。

本地同时重建了 kssh、kssh-daemon、kssh-fleet、kssh-inventory、MCP。
正在运行而被 Windows 锁定的旧 kssh-tui 未覆盖，也没有强制结束它；
如使用友好名称，请使用本次新版桌面、CLI 或 MCP。

真实网络测试默认忽略，仅在明确授权后运行。参数来自进程环境：
`KADUOX_LIVE_JUMP_HOST`、`KADUOX_LIVE_JUMP_USER`、
`KADUOX_LIVE_JUMP_PASSWORD`、`KADUOX_LIVE_TARGET_ALIAS`。
目标密码从该目标对应的系统凭据条目读取，不输出密码；没有保存的目标
密码时测试会明确停止，不搜索其他凭据。
