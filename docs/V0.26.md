# Kaduox-SSH v0.26 development notes

v0.26 closes the remaining cross-platform trust gap in OpenSSH user configuration reads: Windows now validates the owner and DACL of every user-config file before its contents are accepted.

## Windows OpenSSH config trust

The shared `read_user_config_file` boundary is used for the root `~/.ssh/config`, nested `Include` files, and Host catalog discovery. On Windows it now:

- opens the candidate config file first and requires a regular file;
- queries owner/DACL security information from that same open file `HANDLE`;
- accepts owners only from the current user, `BUILTIN\\Administrators`, `LocalSystem`, or a resolvable `TrustedInstaller` SID;
- rejects missing, NULL, or invalid DACLs;
- allows read-only ordinary Allow ACEs for other principals, matching Win32-OpenSSH's user-config `read_ok=1` model;
- rejects untrusted ordinary Allow ACEs carrying file-write, append, extended-attribute write, attribute write, delete, DACL-write, or owner-write authority;
- rejects advanced object/callback/compound Allow ACE layouts rather than approximating their effective rights.

The authorization comparison is SID-based. v0.26 intentionally does not reproduce Win32-OpenSSH's account-name SIDHistory compatibility exception; a distinct SID remains a distinct principal and therefore cannot acquire trust merely because reverse lookup produces the same account name.

## TOCTOU boundary

The Windows implementation deliberately does not use a second pathname lookup such as `GetNamedSecurityInfoW` after opening the file. `GetSecurityInfo` runs on the exact `HANDLE` whose bytes are subsequently read. This preserves the descriptor-bound trust property introduced for Unix in v0.15 and prevents a pathname replacement race from switching the object between ACL validation and parsing.

## Validation

Windows-only tests exercise both sides of the ACL policy by adding a read-only `BUILTIN\\Users` ACE and a write-capable `BUILTIN\\Users` ACE with `icacls`: the former remains readable, while the latter must fail closed.

The normal cross-platform CI matrix remains responsible for compiling and executing the Windows FFI path on `windows-latest`. CI, Quality, and real OpenSSH workflows are wired to `integration/v0.26.0-candidate`. Candidate promotion remains blocked unless those jobs actually acquire runners and execute their steps; `runner_id=0` / empty-step failures are infrastructure evidence, not a passing result.
